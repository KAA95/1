# ВКР: Интеграция сценарного тестирования в процесс разработки 1С

## Назначение репозитория

Репозиторий показывает, как можно организовать пилот автоматизированного сценарного тестирования 1С-решения:

- хранить BDD-сценарии вместе с проектом;
- разделять проверки на `smoke`, `critical` и `regression`;
- использовать теги для управления наборами прогонов;
- готовить тестовые данные и восстанавливать состояние базы;
- запускать сценарии локально и через GitHub Actions;
- сохранять отчеты, логи, скриншоты и параметры запуска как артефакты CI/CD.

## Быстрый старт

1. Настройте self-hosted runner на Windows-машине, где установлены:
   - платформа 1С;
   - Vanessa Automation;
   - Vanessa Runner;
   - доступ к тестовой информационной базе;
   - PowerShell.
2. Скопируйте `config/ci.example.json` в рабочий конфигурационный файл окружения или настройте переменные в GitHub Actions Secrets.
3. Запустите `repository-smoke.yml`, чтобы проверить структуру репозитория.
4. После настройки 1С-инфраструктуры запустите `1c-scenario-tests.yml` вручную через `workflow_dispatch`.

## Локальная проверка структуры

На Linux/macOS:

```bash
bash scripts/check-repository.sh
```

На Windows PowerShell:

```powershell
.\scripts\check-repository.ps1
```

Эта проверка не запускает 1С и Vanessa Runner. Она нужна только для подтверждения, что структура репозитория соответствует проектному решению.

## Локальный запуск сценариев через Vanessa Runner

Пример команды:

```powershell
.\scripts\run-vanessa-tests.ps1 `
  -TagExpression "@smoke and not @unstable" `
  -ResultDir "artifacts/run-local" `
  -SettingsPath "config/ci.example.json"
```

Фактические пути к `vanessa-runner`, тестовой базе, пользователю и обработке Vanessa Automation задаются через переменные окружения.

## Наборы тестов

| Набор | Тег | Назначение | Когда запускать |
|---|---|---|---|
| Smoke | `@smoke` | Быстрая проверка ключевой работоспособности | Каждый pull request |
| Critical | `@critical` | Проверка бизнес-критичных цепочек | Перед слиянием и перед релизом |
| Regression | `@regression` | Расширенная регрессия | Перед релизом или по расписанию |
| Rights | `@rights` | Проверка прав доступа | При изменении ролей и профилей |
| Reports | `@report` | Проверка отчетности | При изменении отчетов и регистров |
| Integration | `@integration` | Проверка обменов и интеграций | При изменении обменов |

## Что нужно адаптировать под реальный проект

- имена документов, справочников, отчетов и ролей;
- команды интерфейса 1С и названия форм;
- путь к тестовой базе и эталонной копии;
- способ восстановления базы;
- реальные обработки подготовки тестовых данных;
- конкретные шаги Vanessa Automation;
- правила публикации отчетов в формате, принятом в организации.
